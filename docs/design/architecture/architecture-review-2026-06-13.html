#1

拆分 rclone/helper.py — 1438 行的扁平 grab-bag 拆成三个深模块

Strong in-process · 拆分 整合 · 为 Rust 重写铺路

javdb/integrations/rclone/helper.py · javdb/integrations/rclone/manager/service.py

Before — shallow
After — three deep modules
Problem

一个 1438 行的扁平模块，55 个函数的接口逼着 service.py 按名导入 27 个符号，跨三个结构无关的 concern：路径处理（8 个纯函数）、子进程扫描引擎（15 个函数，本可只暴露 scan_folder_structure 一个入口）、和驱动 Google Drive 永久删除（rclone purge）的去重引擎（5 个函数）。一处 Rust parse_lsjson_for_year 的迁移欠债埋在 754 行——因为拥有它的 seam 没被隔离而不可见。

Solution

拆成 path_utils.py、scan.py（扫描前置 + FolderCache + parse_folder_name 及其 ADR-041 纯 Python 回退，暴露单一深入口）、dedup.py（DedupResult + analyze_all_duplicates + execute_deletions）。一旦 scan.py 独占该 seam，Rust 迁移欠债自然浮现；被隔离后的删除级联是干净的 Rust 重写目标。

Wins
▪Locality：去重改动只触 dedup.py，Rust 迁移 seam 只现于 scan.py
▪Interface shrinks：scan.py 暴露 1 入口非 15
▪Tests hit one seam per concern，非 55 函数模块
▪Leverage：删除级联成为带编译期不变量的 Rust 目标
无 ADR 重合 ✓ — rclone 区域 ADR 未覆盖；split 保持 parse_folder_name + 回退同处、不引入新 Rust-Required 模块，符合 ADR-041。验证修正：实际导入 27 个符号（非 28），并补入第 4 段（健康检查前置）归入 scan.py。

Problem

dedup.py 把三个深度不同的 concern 塞进一个导入 seam：无 I/O 的纯查询升级逻辑、从 OwnershipLedger/OperationsRepo 加载库存、和持有两个进程全局（须由 autouse fixture 重置）的 DedupRecord 持久化。私有 _normalise_code 被逐字复制进 code_resolver.py（docstring 自承认），而 ops/reconcile 跨兄弟包导入这个私有符号；pipeline/models.py 仅为导 DedupRecord（纯 NamedTuple）就强制每个 importer 加载 Rust bridge 和 OperationsRepo。

Solution

把 DedupRecord/RcloneEntry/DEDUP_FIELDNAMES 提到 spider/contracts.py；将 _normalise_code 升为 parsing/common.py 的公开函数（那里已内联 NFKC 且已被 code_resolver 导入）；dedup.py 拆为纯查询模块与 store 模块（库存加载 + 持久化，两个进程全局藏在清晰 I/O 接口后），给 autouse fixture 一个集中靶点，并移除 ops→spider 私有符号的分层拉扯。

Wins
▪Locality：进程全局只困在 dedup_store，污染不进纯查询测试
▪Deletion test passes：删 dedup_query 暴露调用方，重复 normalizer 消失
▪Interface shrinks：pipeline/models 不再传递性加载 Rust bridge
▪Leverage：消除 ops→spider 分层违例，一个 normalizer 守所有调用方
无 ADR 重合 ✓ — ADR-040（内容过滤）/ADR-033（媒体闭环）拥有 dedup 的业务规则，本候选只动模块切分与符号归位，不改去重判定语义。修复一处真实分层违例（ops 跨包导私有 _normalise_code）。
#3

整合三处重复的 pending_session_verify 记录构建器

Strong in-process · 整合 + 精简 schema 已在漂移

apps/cli/db/commit_session.py · storage/sessions/commit.py · storage/rollback/core.py · integrations/notify/email/service.py

Before — 3 个独立 builder 写同一份 JSONL
After — 1 builder + 3 thin delegates
Problem

三个模块各自构建同一份 pending_session_verify JSONL 记录（一个诊断旁路，非 DB 写），共享 13 字段核心 schema 加各自的扩展。storage/sessions/commit.py 的 _emit_commit_metrics 已被注释为 CLI emitter 的 “Simplified version”——schema 正在漂移。记录解析器 log_analysis._evaluate_pending_alerts 耦合全部三个来源的字段名，无编译期强制。

Solution

抽出纯函数 build_pending_verify_record(...) -> dict 到 storage/sessions/pending_verify.py；三个调用点只供给各自来源专属输入并委托。GITHUB_OUTPUT 写入留在 CLI 作为 post-emit 副作用（确实仅 CLI）；log_analysis 从同一模块导入字段名常量，消除隐式 schema 耦合。

Wins
▪Locality：schema bug 一处修，不再三文件分叉
▪Interface shrinks：一个签名替三个私有实现
▪Tests hit one seam：builder 不需 CLI/rollback 管线即可测
▪Leverage：email 解析器与 builder 由构造共享同一 schema
无 ADR 重合 ✓ — 诊断旁路记录，非 ADR-042 权威/增量/诊断写入边界所定义的 DB 写；纯函数抽取不改任何提交语义。ADR-018 契约 golden 守的是 SQL builder，与此 JSONL 无关。

Wins
▪Locality：HTTP 错误路径收于一个 seam
▪Interface shrinks：lease/report 各减 ~40 行重复

▪Tests hit one seam：mock _do_request 而非 _session.post
无 ADR 重合 ✓ — ADR-023（代理推荐策略）拥有 score 语义，本候选只动 HTTP 传输的去重；ADR-041 只把 ProxyPool/ProxyBanManager 列为 Rust-Required，HTTP client 是纯 Python，不受影响。

#6

把 D1TransientError 的 5 个 monkey-patch 恢复属性提升为声明式 typed interface

Worth exploring in-process · 类型安全 隐形契约 → 编译期错误

javdb/storage/d1_client.py · javdb/storage/d1_port.py · javdb/storage/dual_connection.py

Before — 隐形 monkey-patch 契约
After — 声明式 typed 契约
Problem

D1TransientError 类体为空，但其实例携带跨模块恢复信号（d1_recovery_outbox_required、d1_recovery_durable 在 d1_port.py 设置，d1_recovery_blocker 设在兄弟 RuntimeError），由 dual_connection.py 用防御性 getattr 回退读取——一个隐形接口：拼错会静默默认 False、关掉 outbox recovery 且无可观测失败。

Solution

把三个跨模块恢复信号提升为 D1TransientError 上声明的 typed 字段（移除那 6 处 type: ignore 抑制），并为单一 blocker 赋值点引入 typed D1RecoveryBlockerError(RuntimeError) 子类；dual_connection.py 改为直接读 .d1_recovery_* 并用 isinstance 判定。retry_after/is_export_lock 留作 d1_port 内部低优清理。

Wins
▪Interface：可见的 typed 契约取代隐形 monkey-patch
▪Locality：所有 recovery-signal 语义住在 error 类上
▪Correctness：拼错变成类型错误，非静默关恢复
▪Tests hit the real seam：构造带恢复字段的 error 即可
无 ADR 重合 ✓ — ADR-010（D1 access port）/ADR-042（原子提交边界）拥有 D1 写入策略；本候选只把已存在的恢复信号从 monkey-patch 变成声明式类型，不改恢复行为本身。一个真实的静默失败风险（typo → recovery 被关）被消除。
